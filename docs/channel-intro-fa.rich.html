GitHub Lens Ultra

یک ربات، تمامِ کارِ گیت‌هاب: جست‌وجوی معنایی، پروندهٔ کامل مخزن، تحلیل با استناد، اسکن امنیتی و انتشار با تأیید تو.@Gitguts_bot

گیت‌هاب را ورق نمی‌زنی؛ سؤال می‌پرسی. یک موضوع بنویس یا owner/repo بفرست — ربات از API واقعی گیت‌هاب و OSV عدد می‌گیرد، روی لبهٔ Cloudflare پردازش می‌کند و جواب را همان‌جا، در چت، به تو می‌دهد.

قابلیتمشخصات

🛰 پروندهٔ مخزن۱۲ تب: رشد، ضریب اتوبوس، نرخ مرج، ریلیز، مشارکت، CI، وابستگی، امنیت، چنج‌لاگ، نقشهٔ کد
🧠 تحلیل هوشمند۱۱ مدل در ۳ رده + ردهٔ چندمدلی: چند مدل موازی جواب می‌دهند، یک داور می‌سنجد، خروجی یکی می‌شود
📎 چت با مخزنRAG روی خودِ کد؛ هر جمله با ارجاع به فایل و خط، نه توضیح کلی
🧾 ترجمهٔ READMEساختار، جدول، کد و بج‌ها حفظ می‌شوند؛ صفحه‌به‌صفحه تا آخرین صفحه
🛡 امنیتاسکن وابستگی با OSV، شکار کلید لو‌رفته در تاریخچه، هشدار CVE
📥 تحویل سورسزیپ/تار با لینک امضاشده، تکه‌تکه برای مخزن‌های بزرگ، اسکن امنیتی پیش از تحویل
🧰 جعبه‌ابزارIP/DNS/ASN/TLS، JWT، هش، کرون، CIDR، رجکس، SemVer، JSON و ۱۵ ابزار دیگر — بدون ترک چت

🏗️ معماری در یک نگاه

یک Worker روی لبهٔ Cloudflare همه‌چیز را می‌گرداند: وبهوک تلگرام، مسیرهای فرمان، رندر کارت‌ها و API JSON. داده در D1 (۳۳ جدول، ۴۲ ایندکس)، حالت گفت‌وگو در Durable Objects، کارهای سنگین در Queues، کش در KV، و مدل‌ها روی Workers AI.

  • سه کرون زمان‌بندی‌شده: به‌روزرسانی تخته‌ها، هشدار انتشار و امنیت، و گرم‌نگه‌داشتن کش
  • دروازهٔ سازگار با OpenAI روی همان Worker: POST /v1/chat/completions — هر کلاینتی که OpenAI را می‌شناسد، به این ربات وصل می‌شود
  • هر رویداد یک trace_id دارد؛ از دریافت تا انتشار قابل ردیابی است
  • دریافت وب‌هوکِ بیرونی با امضای HMAC، و صف کارِ پایدار برای پردازش‌های طولانی
📐 چه چیزی این را مهندسی می‌کند، نه تزئینی
  • عدد واقعی، همیشه: آمار از API گیت‌هاب و پایگاه OSV می‌آید؛ هوش مصنوعی فقط خلاصه و تفسیر می‌کند — هیچ عددی ساخته نمی‌شود
  • دروازهٔ تأیید انسانی: هیچ پستی خودکار منتشر نمی‌شود؛ ورک‌فلو پیش‌نویس می‌سازد و منتظر کلمهٔ تو می‌ماند
  • امنیت کلیدها: توکن گیت‌هاب با AES-GCM رمز می‌شود و با یک دستور پاک؛ کلیدهای هوش مصنوعی اهدایی در استخری با مدارشکن و سقف روزانه می‌چرخند و کلید مرده خودکار کنار می‌رود
  • مقاوم در برابر خطا: محدودیت نرخ، ۴۲۹ و خطای گذرا با احترام به retry_after دوباره تلاش می‌شوند؛ سقف روزانهٔ نویورون با زنجیرهٔ جایگزین مدل‌ها مدیریت می‌شود
  • مقیاس‌پذیر در هزینه: کش چندلایه برای دیف، README و تخته‌ها؛ کار تکراری دوباره پرداخت نمی‌شود
🧪 دروازهٔ کیفیت و سورس باز

هر تغییر از یک دروازهٔ محلی و CI می‌گذرد: تایپ‌چک strict، ۲۶۲ تست الگوریتمی، تطبیق اسکیمای D1 با کد، بررسی یکتایی کلیدهای ربات، و تست داون‌گرید پیام‌های تازه به پیام عادی. سورس کامل با مجوز MIT روی گیت‌هاب است — github.com/Alisarani7021/ghlens-ultra
