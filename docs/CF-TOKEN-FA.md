# 🔑 توکن کلودفلر — راهنمای کامل

> این سند پاسخِ «توکن کلودفلر ساختم، حالا چطور ازش استفاده کنم؟» است — از صفر، بدون پیش‌فرض، برای همین پروژه.

---

## ۰) این توکن اصلاً چیست؟

کلودفلر سه چیز متفاوت را «توکن» می‌نامد؛ این سند فقط دربارهٔ **نوع اول** است:

| چیز | شبیه | جای زندگی | خطر |
|---|---|---|---|
| **API Token** ✅ | `cfut_…` (توکن تو) | My Profile → API Tokens | محدود به دسترسی‌هایی که موقع ساخت انتخاب کردی؛ قابل ابطال جداگانه |
| Global API Key ❌ | ۳۷ کاراکتر بدون پیشوند | همان صفحه، پایین‌تر | **دسترسی کامل به کل حساب** — هرگز در هیچ پروژه‌ای استفاده نکن |
| Origin/API key سرویس‌ها | رشته‌های دلخواه | داخل هر سرویس | ربطی به بحث ما ندارد |

یک API Token مثل «کلید کارت‌بانکی با سقف و شماره‌حساب مشخص» است: فقط همان کارهایی که در دسترسی‌هایش نوشته شده می‌کند، فقط روی همان حساب‌هایی که به‌اش داده شده. به همین دلیل همهٔ مسیرهای خودکارسازی (GitHub Actions، wrangler، خودِ ربات) از همین استفاده می‌کنند.

---

## ۱) توکنِ تو دقیقاً چه دسترسی‌هایی دارد؟

این جدول **با تست واقعی روی خودِ توکن** پر شده (هر ردیف یک فراخوانی زندهٔ API بود؛ منابع آزمایشی بلافاصله حذف شدند):

| دسترسی | وضعیت | یعنی چه |
|---|---|---|
| Workers Scripts — **edit** | ✅ | می‌تواند ربات را آپلود/به‌روزرسانی کند (تست: یک ورکر آزمایشی ساخته و پاک شد) |
| Workers KV Storage — **edit** | ✅ | می‌تواند فضای KV بسازد (تست: ساخت+حذف موفق) |
| D1 — **edit** | ✅ | می‌تواند دیتابیس بسازد و اسکیما اجرا کند (تست: ساخت+حذف موفق) |
| Queues — **edit** | ✅ | می‌تواند صف بسازد (تست: ساخت+حذف موفق) |
| Account Settings / فهرست حساب‌ها | ✅ | `GET /accounts` جواب می‌دهد — wrangler به این نیاز دارد |
| Zones — read | ✅ | می‌تواند زون‌های حساب را ببیند (این حساب یک زون دارد: `gitguts.dpdns.org`) |
| Workers AI | ❌ | فراخوانی مستقیم REST هوش مصنوعی با این توکن کار **نمی‌کند** |
| User Details (`GET /user`) | ❌ | این یک دسترسی جداگانه است که به توکن داده نشده — مشکلی ایجاد نمی‌کند (جدول عیب‌یابی پایین) |

**نتیجهٔ عملی:** این توکن برای هر سه کارِ اصلی — دیپلوی از GitHub، دیپلوی با wrangler، و ساخت منابع جدید — **کامل و کافی** است. تنها چیزی که ندارد فراخوانی مستقیم مدل‌های AI با REST است که این پروژه به آن نیاز ندارد (ربات AI را از طریق binding داخلی ورکر صدا می‌زند، نه با توکن).

> **آزمایش خودت، بدون هیچ ابزاری:** این را در ترمینال بزن —
> ```bash
> curl -s https://api.cloudflare.com/client/v4/user/tokens/verify \
>      -H "Authorization: Bearer cfut_…" | jq
> ```
> پاسخ `"status": "active"` یعنی توکن زنده است. برای دیدن دسترسی‌ها: داشبورد → My Profile → API Tokens → روی توکن کلیک کن؛ همهٔ گروه‌های مجاز، همان‌جا لیست شده‌اند.

## ۲) چهار راه استفاده از این توکن

### راه ۱ — GitHub Actions: حلقهٔ خود‌به‌روزرسانی (فعلاً فعال است ✅)

این پروژه یک حلقهٔ کامل خودکار دارد که **الان در حال کار است**:

```text
تو (یا من) به main پوش می‌کنی
   └→ GitHub Actions: CI  → typecheck + ۳۵۰ تست
      └→ deploy.yml → wrangler deploy با CLOUDFLARE_API_TOKEN
         └→ ورکر زنده به‌روز می‌شود (معمولاً زیر ۶۰ ثانیه)
            └→ smoke-test /health بعد از هر دیپلوی
```

آن توکن در **Secret** مخزن گیت‌هاب زندگی می‌کند:

- مسیر: `github.com/Alisarani7021/ghlens-ultra` → **Settings → Secrets and variables → Actions**
- سه رازِ مربوطه: `CLOUDFLARE_API_TOKEN` · `CLOUDFLARE_ACCOUNT_ID` (مقدارش `88a4e920dc6f9606c9987b872ac9ed69` است) · `TELEGRAM_WEBHOOK_SECRET`

**جایگزین‌کردن توکن با توکن تازه** (مثلاً وقتی قدیمی منقضی شود یا بخواهی عوضش کنی): همان صفحه → روی `CLOUDFLARE_API_TOKEN` → **Update secret** → مقدار جدید را بچسبان. همین. هیچ فایلی در ریپو عوض نمی‌شود، چون secret هرگز در کد نیست.

**علامت خرابی توکن در این مسیر:** تب Actions مخزن، وُرک‌فلوی Deploy را قرمز می‌کند با خطای `Authentication error` یا `code 9109`. درمان: به‌روزرسانی راز، همان دو خط بالا.

### راه ۲ — wrangler روی کامپیوتر خودت (کنترل کامل)

```bash
# ۱) پیش‌نیازها: Node 20+ و یک ترمینال
git clone https://github.com/Alisarani7021/ghlens-ultra.git
cd ghlens-ultra && npm install

# ۲) توکن را به wrangler بشناسان (متغیر محیطی — هرگز داخل فایل ننویس)
export CLOUDFLARE_API_TOKEN=cfut_…          # توکن تو
export CLOUDFLARE_ACCOUNT_ID=88a4e920dc6f9606c9987b872ac9ed69

# ۳) ببین wrangler تو را می‌شناسد
npx wrangler whoami

# ۴) دیپلوی (همان کاری که CI می‌کند، این‌بار با دست خودت)
npx wrangler deploy

# ۵) ابزارهای روزمره
npx wrangler tail --format pretty          # لاگ زندهٔ ربات
npx wrangler d1 execute ghlens --remote --command "SELECT COUNT(*) FROM users"
npx wrangler d1 execute ghlens --remote --file=./schema/d1.sql   # مهاجرت
npx wrangler kv key list --binding CACHE   # دیدن کش
```

نکته‌ها:
- wrangler به‌محض دیدن `CLOUDFLARE_API_TOKEN` دیگر مرورگر برای لاگین باز نمی‌کند — توکن کافی است.
- سکرت‌های خود ربات (`BOT_TOKEN` و…) با این توکن قابل **خواندن** نیستند (by design)؛ فقط می‌توانی جایگزینشان کنی: `npx wrangler secret put BOT_TOKEN`.
- منابع (D1، KV، صف) از قبل ساخته شده‌اند و شناسه‌هایشان در `wrangler.jsonc` است؛ wrangler با توکن تو فقط ورکر را آپلود می‌کند.

### راه ۳ — نمونهٔ شخصی، یک‌کلیکی، از داخل خودِ ربات

برای کسی که می‌خواهد **یک کپی مستقل از این ربات** روی حساب کلودفلرِ خودش داشته باشد — بدون کامپیوتر، بدون ترمینال:

1. در ربات: `/hub` → **«🚀 ساخت نمونهٔ شخصی (یک‌کلیکی)»**
2. دکمهٔ **«🔑 ساخت توکن با همین دسترسی‌ها»** داشبورد کلودفلر را با تیک‌های درست باز می‌کند (Workers Scripts/KV/D1/Queues/Workers AI روی edit + دو دسترسی خواندن)
3. توکن ساخته‌شده را در چتِ ربات بفرست (اگر توکن ربات تلگرام خودت را در خط دوم بگذاری، وبهوک هم همان‌جا وصل می‌شود)
4. ربات باندلِ نسخهٔ در حال اجرای خودش را برمی‌دارد و در حساب تو می‌سازد: D1 + دو KV + صف + مهاجرت جدول‌ها + آدرس workers.dev + وبهوک

هر قدم در یک پیامِ ویرایش‌شونده گزارش می‌شود؛ اگر قدمی شکست بخورد، همان قدم و **پاسخ واقعی کلودفلر** نمایش داده می‌شود.

### راه ۴ — مستقیم با API (چیزی که همین سند با آن نوشته شد)

```bash
# سلامت حساب
curl -s "https://api.cloudflare.com/client/v4/user/tokens/verify" \
     -H "Authorization: Bearer cfut_…" 

# فهرست ورکرهای حساب
curl -s "https://api.cloudflare.com/client/v4/accounts/88a4e…/workers/scripts" \
     -H "Authorization: Bearer cfut_…"
```

مستندات کامل: `developers.cloudflare.com/api` — همه‌چیزهایی که در داشبورد با موس انجام می‌دهی همین‌جا با HTTP قابل انجام است.

## ۳) اگر خواستی دسترسی‌ها را کامل‌تر کنی

فقط برای دو کار ممکن است لازم شود دسترسی اضافه کنید:

| می‌خواهی… | دسترسی لازم | کجا |
|---|---|---|
| دیپلوی این پروژه (حالت عادی) | همان که داری — کافی است | — |
| فراخوانی مدل‌های Workers AI با REST (بیرون از ربات) | `Account → Workers AI → Edit` | My Profile → API Tokens → Create Token → Custom |
| دامنهٔ اختصاصی به‌جای `*.workers.dev` (شما زون `gitguts.dpdns.org` را دارید) | `Zone → DNS → Edit` + `Zone → Workers Routes → Edit` | همان صفحهٔ ساخت توکن |

## ۴) قواعد امنیتی (جدی)

1. **توکن = کلید خانه.** فقط در این سه جا می‌تواند باشد: صفحهٔ Secret گیت‌هاب، متغیر محیطی ترمینال، فرم ربات. هرگز در فایل کد، چت، یا اسکرین‌شات.
2. **اگر لو رفت، فقط Roll/Delete کن:** My Profile → API Tokens → روی توکن → **Roll** (همان توکن با مقدار تازه) یا **Delete**. رول کردن ۱۰ ثانیه است و هیچ‌چیز دیگری نمی‌شکند؛ فقط باید مقدار جدید را در همان جاها که قبلاً گذاشته بودی جایگزین کنی.
3. **یک توکن برای یک کار.** توکن CI، توکن لپ‌تاپ، توکن ربات — جدا. اگر یکی لو رفت، بقیه سالم‌اند.
4. **توکنِ گیت‌هاب را هم همین‌طور جدی بگیر** — همان صفحه‌ٔ معادل در گیت‌هاب: Settings → Developer settings → Tokens (classic/fine-grained) → Regenerate.

## ۵) عیب‌یابی سریع

| نشانه | معنا | درمان |
|---|---|---|
| `code 9109: Unauthorized to access requested resource` | توکن آن دسترسیِ خاص را ندارد | جدول §۱ را ببین؛ توکن را ویرایش/بساز |
| `Authentication error` روی `/ai/models` | دسترسی Workers AI نیست | برای این پروژه لازم نیست؛ نادیده بگیر |
| GitHub Actions قرمز با `Authentication error` | راز `CLOUDFLARE_API_TOKEN` منقضی/غلط است | Settings → Secrets → Update |
| `wrangler deploy` → `workers.api.error` ناشناخته | معمولاً اشتباه بودن `CLOUDFLARE_ACCOUNT_ID` | مقدار درست: `88a4e920dc6f9606c9987b872ac9ed69` |
| `/user` خطای 9109 می‌دهد | `user_details:read` نیست | عادی است — wrangler و CI به آن نیاز ندارند؛ از `/user/tokens/verify` استفاده کن |
